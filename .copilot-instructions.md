# GitHub Copilot Instructions for SAP CF MCP Server

## 🎯 **Project Context**
This is a Node.js Model Context Protocol (MCP) server specifically designed for SAP BTP Cloud Foundry development. It provides three main tools for parsing MTA files, managing XSUAA authentication, and querying Cloud Foundry APIs.

## 🏗 **Architecture Understanding**
- **Language**: TypeScript/Node.js with ES modules
- **Protocol**: Model Context Protocol (MCP) with stdio transport
- **Target**: SAP BTP Cloud Foundry applications
- **Integration**: GitHub Copilot and VS Code compatible
- **Design**: Cross-repository usage enabled

## 🔧 **Key Components**

### **MCP Tools Available**
1. **`parse_mta`** - Parse mta.yaml files and extract resource/module information
2. **`get_access_token`** - Obtain OAuth2 tokens from XSUAA service using client credentials
3. **`get_cf_resources`** - Query Cloud Foundry API for applications, services, spaces, organizations

### **Core Services**
- **XSUAAAuthService**: OAuth2 authentication with token caching
- **CloudFoundryAPIService**: CF API client with comprehensive error handling
- **MTAParser**: MTA descriptor parsing and validation

### **File Structure Awareness**
```
src/
├── index.ts              # Main MCP server entry point
├── services/            # Authentication and API services
├── tools/              # MCP tool implementations
├── utils/              # Logger and MTA parser utilities

```

## 🚀 **Development Patterns**

Always use the enhanced error logging:
```typescript

try {
  // operation

  logError('Operation description', error, { contextKey: 'contextValue' });
```

### **MTA Processing Pattern**
```typescript
// Parse MTA descriptor
const mta = await MTAParser.parseFromFile(filePath);

// Extract XSUAA credentials from resources
const xsuaaResource = mta.resources?.find(r => r.type === 'org.cloudfoundry.managed-service' &&
  r.parameters?.service === 'xsuaa');

// Use credentials for authentication
const authService = new XSUAAAuthService(xsuaaCredentials);
const token = await authService.getAccessToken();
```

### **Cloud Foundry API Pattern**
```typescript
// Initialize CF API client
const cfApi = new CloudFoundryAPIService(baseUrl, authService);

// Query resources with proper error handling
const result = await cfApi.getApplications();
if (result.success) {
  // Process result.data
} else {
  // Handle result.error
}
```

## 📋 **SAP BTP Specific Context**

### **XSUAA Authentication**
- Uses OAuth2 client credentials flow
- Requires: `clientid`, `clientsecret`, `url`, `identityzone`, `tenantid`
- Tokens are cached with expiration handling
- Scope management for different CF API operations

### **MTA Descriptor Structure**
- Contains modules (applications) and resources (services)
- XSUAA service typically defined as managed service resource
- Binding relationships between modules and resources
- Environment-specific parameters and properties

### **Cloud Foundry API Integration**
- Base URL typically: `https://api.cf.{region}.hana.ondemand.com`
- Requires Bearer token authentication
- Supports pagination for large result sets
- Returns structured JSON responses

## 🎯 **Common Development Tasks**

### **Adding New MCP Tools**
1. Create tool definition in `src/tools/new-tool.ts`
2. Export tool object and handler function
3. Register in main server (`src/index.ts`)
4. Add CLI support in `scripts/mcp-cli.js`
5. Update TypeScript types if needed

### **Extending CF API Support**
1. Add new methods to `CloudFoundryAPIService`
2. Define response types in `src/types/index.ts`
3. Implement proper error handling and logging
4. Add corresponding MCP tool if needed

### **MTA Parser Enhancements**
1. Extend `MTADescriptor` interface for new properties
2. Add validation rules in `MTAParser.validateMTADescriptor()`
3. Update parsing logic for new MTA features
4. Maintain backward compatibility
